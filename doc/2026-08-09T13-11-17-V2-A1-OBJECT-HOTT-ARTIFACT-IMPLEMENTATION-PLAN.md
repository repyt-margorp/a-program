## 1. Objective

Publish the object-language results of the first Higher Observational Type
Theory fragment through the artifact boundary.

The artifact must preserve and replay:

```text
Gamma |- R : Universe

Gamma |- p : R
```

when `R` and `p` were generated by the admitted O1 Type and Term actions.

The artifact must not serialize the compiler search that found those objects.
In particular, these remain compiler-local and rebuildable:

- observation goals;
- candidate rules and child-goal edges;
- work items and fuel accounting;
- residual records;
- action requests and action results;
- action certificates;
- bridge records and bridge certificates; and
- Context/substitution formation-certificate caches.

The persistent authority is the ordinary object graph:

- TermDB observation formers and their APP spines;
- accepted `IS_TYPE` and `HAS_TYPE` Claims;
- accepted Derivations and their exact premise Claim edges;
- ContextDB and SubstitutionDB objects referenced by those Claims and
  Derivations; and
- a small artifact root table identifying which accepted object Claims are
  intentionally published as observational results.

## 2. Non-Negotiable Design Decisions

### 2.1 Publish object evidence, not compiler execution history

V2-O1 separates immutable action requests, mutable result state, and accepted
object Claims. V2-A1 must preserve that separation.

An action result is evidence that the compiler successfully constructed an
object. It is not itself the object proof. The artifact root therefore names
the resulting accepted Claims and does not name an action request, result,
bridge, candidate, work item, fuel budget, or compiler graph revision.

### 2.2 Add an explicit observation-root table

Generated HOTT objects currently need not have a surface name and therefore
are not necessarily reachable from `prototype_artifact_term_export`.
Publishing every accepted observation Claim would also be wrong: it would make
artifact contents depend on incidental compiler search and unused successful
candidates.

Add one explicit interface record:

```c
struct prototype_artifact_observation_root {
	uint32_t relation_is_type_claim_id;
	uint32_t witness_has_type_claim_id;
};
```

`witness_has_type_claim_id` may be `PROTOTYPE_INVALID_ID` for a family-only
result such as an observational family for distinct constructors. The relation
Claim is always required.

Do not duplicate these Claim-owned fields in the root:

- Context id;
- relation or witness Term id;
- classifier Term id;
- source endpoint Claims;
- source bridge id;
- category;
- proof kind; or
- action rule.

Those values are already fixed by the accepted Claim/Derivation closure.
Duplicating them would create a second semantic authority.

### 2.3 Root extraction and artifact registration are separate operations

Add a HOTT-side extraction API that accepts validated READY action results and
returns the two accepted Claim ids. It must reject:

- residual or unsupported results;
- a Term result not tied to the supplied Type-action request;
- a missing or invalid action certificate;
- a relation Claim that is not `IS_TYPE`;
- a witness Claim that is not `HAS_TYPE`; and
- a witness whose accepted premise closure does not reach the supplied Type
  action's relation Claim through the exact reindex/instantiation derivations.

Add an artifact-side registration API that interns the exact Claim pair in the
interface root table. Artifact code must not depend on action DB internals.

This keeps the ownership direction:

```text
HOTT action execution
    -> accepted object Claims
    -> publication-root extraction
    -> artifact interface registration
```

### 2.4 Use artifact v70 with no compatibility reader

V2-A1 changes the wire calculus and must increment
`PROTOTYPE_ARTIFACT_FORMAT_VERSION` from 69 to 70.

Create `src/prototype/artifact_v70.schema` and update the general artifact
calculus fingerprint from its exact bytes. The reader accepts only v70 after
the migration. Do not add a v69 compatibility branch, optional legacy parser,
unused compatibility slots, or remap shim.

Historical schema files may remain documentation, but they are not accepted
wire formats.

### 2.5 Keep the HOTT and artifact fingerprints distinct

`hott_fragment_v2.schema` fingerprints compiler-local action semantics.
`artifact_v70.schema` fingerprints the persistent object/wire calculus.

The artifact header needs only the v70 artifact fingerprint. It must not embed
the action-result fingerprint, graph revision, or fuel budget. Tests must still
ensure that the shared numeric object tags and proof kinds agree between C
headers and both manifests where their domains overlap.

## 3. Current Codebase Audit

### 3.1 O1 object terms exist but v69 cannot write them

`src/prototype/term.h` defines:

```text
PROTOTYPE_TERM_OBSERVATION_TYPE_FORMER    = 32
PROTOTYPE_TERM_OBSERVATION_WITNESS_FORMER = 33
```

They are graph-consed, reindexed, hashed, normalized, and validated by
`src/prototype/term.c`. Observation types and witnesses are represented as APP
spines headed by these nullary formers.

The artifact boundary is incomplete:

- `write_artifact_term()` in `src/prototype/ast.c:3391` has no cases for tags
  32 and 33;
- `read_artifact_term()` at `src/prototype/ast.c:7693` has no cases for them;
- `artifact_validate_term_refs()` at `src/prototype/ast.c:8128` does not admit
  them as leaf nodes; and
- `artifact_v69.schema` ends at term tag 31.

The sparse marker currently treats unknown leaf tags as leaves. That accidental
default is not sufficient authority. Tags 32 and 33 must be explicit in every
wire switch and in the schema.

### 3.2 O1 proof kinds exist but the reader rejects them

`src/prototype/judgement.h` defines accepted proof kinds 33 through 42:

```text
OBSERVATION_TYPE_FORMATION
OBSERVATION_WITNESS_INTRO
SUBSTITUTION_REINDEX
OBSERVATION_CONSTRUCTOR_WITNESS
OBSERVATION_RETURN_WITNESS
OBSERVATION_THUNK_WITNESS
OBSERVATION_APP_WITNESS
OBSERVATION_LAMBDA_WITNESS
OBSERVATION_MATCH_WITNESS
OBSERVATION_INDUCTION_HYPOTHESIS_WITNESS
```

`prototype_judgement_db_validate()` already replays these rules in
`src/prototype/typing.c`. The graph writer is generic enough to print their
accepted Derivations.

The v69 reader at `src/prototype/ast.c:9072` rejects every proof kind greater
than `PROTOTYPE_JUDGEMENT_PROOF_EFFECT_WEAKEN` (32). The v70 reader must use the
frozen last O1 proof kind and must still reject unknown future integers.

### 3.3 Scoped-premise readback is currently miswired

The derivation reader passes
`scoped_premise_context_ids[j]` twice to one `fscanf` call. Consequently the
wire tokens intended for subject and classifier are shifted and the classifier
destination is not populated correctly.

Existing artifact fixtures do not expose this because their accepted replay
closure does not adequately exercise nontrivial scoped premise tuples after
readback. O1 Lambda and Match witnesses do.

This is a precondition bug, not an optional cleanup. It must be fixed and given
an independent v69-baseline regression fixture before adding HOTT roots.

### 3.4 Sparse publication has no root for unnamed HOTT objects

`artifact_mark_roots()` at `src/prototype/ast.c:6033` starts from named term
exports, type exports, constructor exports, and compile metadata. It has no
root path from a completed O1 action.

`artifact_mark_accepted_claim()` already computes the required transitive
closure:

- Claim subject and classifier Terms;
- every accepted Derivation concluding the Claim;
- exact premise Claims;
- scoped premise subject/classifier Terms;
- constructor owner views;
- induction Match and motive Terms; and
- lower closure ranks only.

V2-A1 should reuse this closure. It must not introduce a second HOTT-specific
proof walker.

### 3.5 Context and Substitution data are already serializable

The graph writer builds a reachable Context slice from accepted Claims and
Operation metadata. Structural Substitutions and the semantic substitution
action edge used by `CONTEXT_WEAKEN`/`SUBSTITUTION_REINDEX` are already part of
the v69 graph contract.

Therefore V2-A1 does not need a serialized bridge DB or certificate DB. Once an
observation root marks its Claims, existing Context/Substitution reachability
must carry the required object-level scope. The new tests must verify this
rather than adding duplicate HOTT context records.

### 3.6 Append/link must relocate observation roots

`prototype_artifact_append_graph()` at `src/prototype/ast.c:11338` relocates
Terms, binders, Contexts, Substitutions, Claim candidates, Derivation
candidates, and existing interface exports. It currently knows nothing about
observation roots.

For each appended root it must relocate:

```text
relation_is_type_claim_id += claim_candidate_offset
witness_has_type_claim_id += claim_candidate_offset, unless INVALID
```

The capacity preflight, interface initialization, copy path, and validation
must include the new root arena. No post-link search by Term shape may replace
this exact Claim-id relocation.

### 3.7 Relocation and dependency discovery should remain generic

Observation former nodes are closed nullary constants. Their APP arguments and
proof premises carry any external references. Once the sparse graph contains
the marked Claim closure, the existing relocation scan over present Terms and
Judgements should discover dependencies.

Do not add a separate HOTT dependency table. Add tests proving that imported
endpoint Terms referenced only through an observation root produce ordinary
artifact dependencies and relocations.

### 3.8 Compiler-local records must not leak into the wire

The following structures in `src/prototype/hott.h` contain allocation-local or
execution-local ids and must not be added to `prototype_artifact_interface`:

- `prototype_hott_bridge` and `prototype_hott_bridge_certificate`;
- `prototype_hott_observation_goal`;
- `prototype_hott_candidate` and premise arenas;
- `prototype_hott_work_item`;
- `prototype_hott_action_request`;
- `prototype_hott_action_certificate`; and
- `prototype_hott_action_result`.

Serializing them would make artifact identity depend on search order, fuel,
cache allocation, and compiler graph revision.

## 4. Target Wire Contract

### 4.1 Interface section

Add a counted sparse-free root table to the interface section:

```text
observation_roots N
observation_root RELATION_CLAIM WITNESS_CLAIM
```

Root records are dense interface records, unlike sparse graph slots. Duplicate
exact pairs are interned and emitted once. A relation-only root writes the
unsigned representation of `PROTOTYPE_INVALID_ID` for the witness field, in the
same style as existing graph ids.

### 4.2 Graph section

The graph section retains the existing sparse Claim/Derivation representation.
Extend only the frozen enums and term payload rules:

- term tags 32 and 33 are nullary;
- proof kinds 33 through 42 use the existing Derivation record;
- premise order remains part of proof identity;
- scoped premise tuples remain explicit; and
- semantic action id is serialized only for the already admitted substitution
  action kind.

Do not add HOTT-specific proof payload fields. O1 deliberately encoded the
necessary evidence in exact premise Claim edges and existing Derivation fields.

### 4.3 Root validity

An observation root is valid only when:

1. the relation id names a present accepted `IS_TYPE` Claim;
2. that Claim has at least one accepted derivation whose proof kind is
   `OBSERVATION_TYPE_FORMATION`;
3. every derivation/premise in its closure replays successfully;
4. an optional witness id names a present accepted `HAS_TYPE` Claim;
5. the witness Claim has at least one admitted O1 observation-witness
   derivation;
6. the witness derivation closure reaches the root relation Claim through exact
   accepted premise edges and its classifier is the resulting reindexed
   relation instance, not merely a convertible unrelated type; and
7. relation and witness scopes are present in the serialized Context slice.

The root table does not assert DefEq and does not add any relation to kernel
conversion.

### 4.4 Import meaning

In A1, observation roots are module-level proof certificates available to the
linker and future tooling. They are not surface names and are not resolved by
ordinary identifier lookup.

Import/readback must preserve and replay them, and append/link must retain them.
Surface `==`, proof names, transport, rewrite, and cross-module proof selection
remain later stages.

## 8. Risks and Required Resolutions

### 8.1 Rooting all Claims would leak search history

Do not serialize every HOTT Claim merely because it is accepted. Only explicit
publication roots and their proof closure belong to the artifact.

### 8.2 Term identity alone is insufficient

The same shared Core Term may have distinct typed Operations and Claims. Root
identity must use accepted Claim ids, not canonical Term keys or raw subject
Term ids.

### 8.3 Action certificates are not stable wire objects

Their ids point into compiler-local bridge, Context-certificate, and
Substitution-certificate arenas. Persisting them would require serializing
search infrastructure and would duplicate accepted Claim authority.

### 8.4 Sparse slots require presence checks

Every root and premise reference must require both an in-range id and a present
slot. A range check alone accepts holes and is insufficient.

### 8.5 Multiple Derivations are intentional

One accepted Claim may have multiple valid Derivations. Sparse closure should
retain all accepted derivations for a rooted Claim, as the current marker does.
Do not select or serialize a preferred proof.

### 8.6 Compiler replay must not upgrade object equality to DefEq

Reading an observation witness establishes an ordinary `HAS_TYPE` Claim. It
must not mutate normalization profiles, conversion caches, or a global
equality/union structure.

### 8.7 Higher structure must not be erased

Observation-of-observation Claims must round-trip as ordinary typed relation
fields and witnesses. No Unit/Empty lowering, proof irrelevance, or
set-truncation is permitted in artifact serialization.

## 9. Explicit Non-Goals

V2-A1 does not:

- add surface `==`, `refl`, transport, rewrite, or proof declarations;
- serialize unresolved HOTT residuals;
- serialize action requests/results/certificates;
- add equality reflection;
- add observational proofs to DefEq;
- implement symmetry, transitivity, transport, or J;
- implement univalence or Universe equality;
- add HIT quotient computation for machine integers;
- define effect-handler contextual equivalence;
- expose observation roots through ordinary source-name lookup; or
- add separate value-side and computation-side Term graphs.
