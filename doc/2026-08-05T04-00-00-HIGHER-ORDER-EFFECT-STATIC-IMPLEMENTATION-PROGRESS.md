## 3. Invariants

1. TermDB row binders are durable syntax and never mutable solver cells.
2. Solver metavariables live only in compiler-local arenas.
3. A solver result enters TermDB only through an explicit materialization step.
4. Effect inclusion is not definitional equality or value subtyping.
5. A parameterized effect atom does not add a second runtime operation node.
6. Generic folds do not traverse `THUNK` automatically.
7. Partial policy may preserve residual obligations but must not claim a valid
   export classifier.
8. Strict policy accepts only proofs replayable by the artifact kernel.
9. Runtime success is not evidence of static closure.
10. Existing examples and artifact behavior must not regress.

## 5. Stage 1: Solver Row Metavariables

### 5.1 Current authority violation

`operation_effect_solve_constraints` recognizes an unsolved
`EFFECT_ROW_VAR(result_row)` and calls `operation_effect_substitute`. That
function rewrites every known classifier, binder classifier, solver binding,
and effect constraint containing the same binder ID.

This conflates three identities:

1. a quantified row variable in a classifier;
2. an occurrence-local unknown generated by inference; and
3. a solver cell whose binding changes during fixed-point iteration.

It also makes the scope of a solution depend on binder-ID uniqueness rather
than an explicit constraint owner.

### 5.2 Target representation

The compiler-local effect solver owns an arena of row metavariables. Each entry
contains:

- a stable solver ID;
- the operation occurrence which owns it;
- an unsolved or solved state;
- a solved TermDB row ID only after closure; and
- optional diagnostic origin information.

Constraint operands distinguish durable TermDB rows from solver metavariables.
No meta ID is serialized as a TermDB ID.

### 5.3 Migration sequence

- [ ] Introduce the compiler-local row-meta arena and discriminated operands.
      The arena exists and JudgementDelta residuals are local, but persistent
      diagnostic constraints still use TermDB row operands.
- [x] Register inference-owned unknown result rows by owner occurrence and
      placeholder row, rather than using binder identity as solver-cell identity.
- [x] Resolve solved meta state through the owner-scoped arena.
- [x] Materialize solved rows into only the owning occurrence's classifiers.
- [x] Remove global binder substitution from the effect solver.
- [x] Keep genuine enclosing `forall E` binders out of occurrence-meta solving.
- [x] Ensure artifact output contains solved rows or explicit residual
      obligations, never solver-meta IDs.

### 5.4 Acceptance evidence

- two independent unknown rows cannot solve each other through a shared binder;
- a quantified operation declaration remains unchanged after occurrence
  specialization;
- repeated fixed-point passes do not grow or rewrite unrelated classifiers;
- partial and strict policies retain their current distinction;
- all existing tests pass.

## 6. Stage 2: Join and Inclusion Constraints

The solver will add first-class constraints for:

```text
F = join(E1, E2, ..., En)
E1 <= F
E2 <= F
...
```

The first implementation may solve closed bitset rows exactly and retain
symbolic rows as residuals. It must not approximate an unknown row as empty.

Planned work:

- [x] Add n-ary join constraints to the JudgementDelta solver. TermDB may still
      hash-cons a binary union expression, but the solver evidence is n-ary.
- [x] Add row-inclusion constraints.
- [x] Normalize duplicate and empty closed-row operands by bitset union.
- [x] Detect closed contradictions.
- [x] Retain unsupported symbolic constraints under partial policy.
- [x] Reject unresolved constraints under strict policy.

## 7. Stage 3: Effect Weakening Proof

Add a runtime-erased proof rule:

```text
M : Comp(E1, A)    E1 <= E2
--------------------------------
M : Comp(E2, A)
```

Planned work:

- [x] Add `PROTOTYPE_JUDGEMENT_PROOF_EFFECT_WEAKEN`.
- [x] Require one source has-type premise and independently replay closed row
      inclusion in the proof validator.
- [ ] Use it to align every return and clause computation with the solved fold
      row. Closed abortive clauses now align; symbolic latent rows remain.
- [x] Keep the rule parameter-free so existing generic proof
      serialization/relocation preserves its sole has-type premise.
- [x] Replay closed row inclusion when artifact proofs are kernel-validated.
- [x] Reject widening which changes the computation result type or removes an
      existing effect.

## 8. Stage 4: Parameterized Operation Atoms

Add a durable row expression schematically equivalent to:

```text
scope<E>
```

It identifies one operation family together with latent row arguments. It is
static row data and does not change runtime dispatch.

Planned work:

- [x] Define the TermDB representation and canonical hashing.
- [x] Support traversal, substitution, normalization comparison, printing,
      reachability, relocation, serialization, and readback validation.
- [ ] Instantiate one atom per request occurrence.
- [ ] Preserve distinct latent rows for distinct occurrences.

The first two items establish durable syntax only. They do not change the
classifier currently inferred for an operation request.

## 9. Stage 5: Handler Elimination and Fold Carrier

For a handled parameterized atom, the handler rule decides whether the latent
row is discarded, exposed by force, or transformed by an explicit inner fold.
The fold carrier is then solved from all branch and residual rows.

Planned work:

- [ ] Generate handled-atom elimination constraints.
- [ ] Join return, clause, and residual rows.
- [ ] Feed the solved carrier into continuation classifiers.
- [ ] Iterate until classifier and row constraints reach a fixed point.
- [ ] Reify `COMPUTATION_FOLD_ELIM` only after every required weakening proof
      exists.

## 12. Progress Log

### 2026-08-05: Parameterized row representation added; authority boundary found

- Added `PROTOTYPE_TERM_EFFECT_ROW_OPERATION(operation_id, latent_row)` without
  adding a runtime request tag.
- Covered canonical identity, graph traversal, substitution, normalization,
  printing, artifact reachability, relocation, v58 serialization, readback,
  and reference validation.
- Confirmed that merely generating the atom in request inference is premature.
  `OPERATION_REQUEST_INTRO` currently omits the argument occurrence and its
  selected classifier from its proof premises.
- Confirmed a second authority conflict: OperationGraph may retain a
  provisional closed request classifier after JudgementDB derives a more
  precise occurrence classifier. The OperationGraph proof materializer can
  then rebuild an enclosing fold against the stale classifier.
- Rejected a normalization-equality patch between those proofs. The required
  fix is to make the argument occurrence explicit in the request proof, bind
  the request OperationGraph node to that proven classifier, and defer fold
  proof reification until that binding exists.
- Kept automatic atom generation and handled-atom elimination disabled at this
  checkpoint. The existing CBPV surface suite passes with the representation
  changes alone.

### 2026-08-05: Ledger created

- Re-read the decision record against `term.h`, `judgement.h`, `typing.c`, and
  the OperationGraph solver in `ast.c`.
- Confirmed that current effect constraints persist TermDB row IDs into the
  artifact, while the solver mutates classifier graphs by binder substitution.
- Confirmed that `JudgementDelta` separately creates a fresh TermDB row binder
  for an unresolved fold residual. Both paths must migrate; changing only the
  artifact-side constraint structure would leave the kernel path inconsistent.
- Fixed the implementation order: row-meta separation precedes join,
  weakening, and parameterized atoms.

### 2026-08-05: Fold residual placeholder removed from TermDB

- Added explicit solver-local pending state to each computation constraint.
- Removed creation of a fresh `EFFECT_ROW_VAR` when a clause-bearing fold
  residual cannot yet be computed.
- The residual equation is now emitted only after its result is a real TermDB
  row. This prevents an unsolved kernel constraint from masquerading as a
  durable quantified row.
- At this checkpoint Stage 1 remained in progress because the OperationGraph
  solver still used global binder substitution. The following milestone
  removes that path.

### 2026-08-05: OperationGraph row solutions made occurrence-local

- Added a compiler-local effect-row meta arena keyed by owner operation and
  placeholder row.
- Factored explicit ownership checking for effect-row binders. A row quantified
  by an enclosing lambda is retained as symbolic syntax and is not solved as an
  occurrence meta.
- Replaced global substitution over every operation classifier and constraint
  with controlled materialization into the owning occurrence only.
- Kept dependent occurrences on the existing fixed-point propagation path
  instead of mutating them because they happen to contain the same binder ID.
- The complete prototype suite and examples 01-09 passed after this change.

### 2026-08-05: N-ary row constraints introduced

- Replaced JudgementDelta's binary effect-row equation representation with a
  variable-arity constraint representation.
- Added `JOIN`, `RESIDUAL`, and `INCLUSION` constraint kinds.
- Recorded all handled operation rows as one n-ary JOIN constraint.
- Recorded return-row and residual-row inclusion in the current fold carrier.
- Closed constraints are checked exactly by bitset semantics; symbolic cases
  remain unsolved rather than being approximated.
- `test_cbpv_surface.sh`, `test_artifact_flow.sh`, the full prototype suite, and
  examples 01-09 passed. Artifact diagnostic constraints remain binary until
  Stage 3 supplies proof-level inclusion data.

### 2026-08-05: Closed effect weakening rule added

- Added `PROTOTYPE_JUDGEMENT_PROOF_EFFECT_WEAKEN` with one source has-type
  premise.
- The producer and independent proof validator both require computation types,
  normalization-equal result types, closed rows, and subset inclusion.
- Kept row inclusion out of conversion and DefEq.
- Added a direct CBPV boundary test which accepts pure-to-terminal widening and
  rejects a target with a changed result type.
- The complete prototype suite and examples 01-09 passed.
- Fold integration records weakening on the returned computation body. It does
  not rebuild the enclosing Lambda/Pi classifier; the fold rule separately
  validates branch-row inclusion in its carrier.

### 2026-08-05: Closed fold carrier join integrated

- OperationGraph now computes a monotone closed-row carrier from the return
  body, known clause bodies, and the unhandled input residual.
- A clause body becoming classified re-enqueues its owning fold constraint.
- Continuation binder classifiers may widen only in the specific shape
  `Thunk(Pi(B, Comp(E, C)))`, preserving `B` and `C` and requiring `E` to grow
  by closed-row inclusion.
- Added `effect_weaken_handler_check.p`: a pure return clause and an abortive
  `{print}` clause produce `Comp({print}, Text)`, pass strict policy, survive
  artifact readback, print `handled`, and return `"abort"`.
- Strengthened clause-bearing fold proof validation. Closed carriers are
  checked exactly; symbolic carrier comparisons are accepted only as residual
  partial-policy obligations and remain rejected by strict policy.
- Existing force-once behavior remains partial: it executes, but strict
  verification still rejects its unresolved latent row.

### 2026-08-05: Principal Lambda effects separated from weakening

- A shared core Lambda had both a pure Pi derivation and a widened `{print}` Pi
  derivation. Candidate selection treated them as unrelated and failed; a
  later workaround also produced a Lambda proof with the wrong binder context.
- Removed the workaround which rebuilt the enclosing Lambda after weakening.
  `EFFECT_WEAKEN` now applies only to the computation body used as branch
  inclusion evidence.
- Lambda synthesis no longer feeds an `EFFECT_WEAKEN` result back into Pi
  synthesis. For otherwise equal closed Pi candidates, selection keeps the
  least effect row; incomparable or symbolic candidates still fail.
- The closed abortive handler fixture passes strict compilation and artifact
  readback. It prints `handled`, returns `"abort"`, and does not execute the
  discarded `"inner"` thunk.
- Partial higher-order force artifacts retain their current classifier
  approximation together with residual obligations. Strict policy still
  rejects those artifacts until occurrence-local latent rows are solved.

## 13. Deviation Log

### 2026-08-05: Artifact diagnostic constraint compatibility retained

The durable proof format is not changed merely to serialize compiler-local
n-ary constraints. Existing artifact effect constraints remain binary
diagnostic records for materialized JOIN/RESIDUAL cases. N-ary JOIN and
INCLUSION become artifact authority only through the Stage 3 proof format.
This avoids exposing solver internals as program graph syntax.

### 2026-08-05: Fold carrier inference spans OperationGraph and JudgementDB

The original plan described fold carrier solving mainly as a JudgementDelta
task. Implementation showed that continuation binder classifiers are required
while OperationGraph is still reaching its fixed point. The revised boundary
is:

- OperationGraph computes a monotone carrier approximation for elaboration;
- JudgementDB reifies and validates the final weakening/fold derivations;
- artifact validation independently replays closed carrier structure;
- symbolic comparisons remain verification obligations, never strict proof.
