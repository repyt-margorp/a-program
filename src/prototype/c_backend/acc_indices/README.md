# Actual Acc LT constructor index candidate

This finite candidate derives LT constructor field classifiers and ordered result
images from the existing admitted declaration views. Actual `step(k, succ k)`,
`weakenRight(m, succ n)` and `lift(succ m, succ n)` recipes drive refinement index
checks and Nat field selection in the executable actual Acc QuickSort C module.
It preserves the C51 source map/endpoint/frame/down-direction recipe prefix and
all seven source algorithm bodies. Concrete Nat/LT storage, role values, closures
and array lifetime/copy-out remain target-authored. It does not substitute a
sorter, admit a declaration, invent source erasure or claim general native success.

The reader uses `pg_data_declaration_pack` for borrowed declaration root slices,
with new arrays allocated only in target scratch storage. It checks the closed
two-Nat-index/three-constructor shape, Nat field classifiers, exact Self-applied
prior field and direct/one-successor result images. Other shapes refuse; no
source equation solving or numeric cancellation is attempted. Its standalone
recipe API is target inspection, not source checking. Public source admission
precedes helper emission, with source-owner snapshots and advancement guards.

`fixture.p` contains three separately admitted declarations which remain target
refusals: two successors in a result image, an extra step field and a Nat prior
field. The qualification setup combines these definitions with the unchanged
actual fixture, omitting only the already-present Nat import. These are explicit
source-to-target limitations, not upstream errors or accepted-source deletions.

`pack.py EXACT_C51_OR_C52_PRODUCT QUALIFIED_INDEX_RECIPE NEW_OUTPUT` replaces only
the scoped action section after checking parent/recipe bytes. Products expose
the unchanged `gs_sort` header/ABI as ordinary source, object and archive. The
source algorithm remains emitted from its actual admitted bodies; historical
module bytes qualify the fixed candidate and label manual target extent.

`check.sh HELPER IMAGE EXACT_PARENT_PRODUCT CORE_CASES POINTER NEW_OUTPUT` runs
serial focused source/product/resource/Core/refusal controls. `CLIENT_CFLAGS`
selects O2 or whole generated-source/client sanitizer builds; the helper is built
separately with matching flags. Core inputs are retained producer-oracle cases,
not a new source oracle. No comparative workload is performed.

General indexed/callable native Acc/QuickSort, full checked Scope/source action
equivalence, accepted adoption and actual costs remain open. Nat32/depth256/
node65536, borrowed immutable/nonoverlap/private-token lifetime, status1-6 and
transactional output remain. Finite SAN is not arbitrary pointer proof; the
output overflow guard is unexercised. Main native4/input3/private16 controls are
historical/separately qualified; this candidate does not reinterpret them.
