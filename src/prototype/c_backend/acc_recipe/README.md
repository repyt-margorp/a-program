# Actual Acc down/action recipe candidate

This bounded candidate derives the `Acc.acc` callback's LT domain indices and
recursive result index from its existing admitted constructor classifier. It also
reads the actual Identity field endpoints/directions. The generated recipe drives
the executable C action's inverse callback-domain remapping and result-index
check, retaining the original nominal edge, proof, down callback, capture, maps
and paths. It keeps the source QuickSort algorithm and existing `gs_sort` ABI.

For the actual source, constructor field0 is the captured Nat index; field1 is
`down`. Its arguments are Nat and LT(argument0,captured0), and its pure TOTAL
result is Self(argument0). The step field transports quoted Acc left-to-right;
the other two fields transport LT right-to-left. These choices come from source
syntax and exact nominal declarations, not equal machine integers. Other
relations, argument orders, parameter types or classifier shapes refuse.

Build the helper serially against the explicitly qualified producer tree:

```sh
make -j1 -f src/prototype/c_backend/acc_recipe/build.mk \
  OVERLAY=/absolute/qualified/tree BUILD=/absolute/owned/build \
  CFLAGS='-std=c11 -Wall -Wextra -Werror -O2' \
  /absolute/owned/build/c_acc_recipe_emit
/absolute/owned/build/c_acc_recipe_emit \
  /absolute/actual-materialized.a /absolute/recipe.inc succ_access
python3 src/prototype/c_backend/acc_recipe/pack.py \
  /absolute/qualified-C50-product /absolute/recipe.inc /absolute/new-product
cc -std=c11 -O2 -I/absolute/new-product ordinary_client.c \
  /absolute/new-product/component.c -o ordinary_client
```

The [readable example](example/component.c) and [declarative header](example/component.h)
are regenerated by that packer. Products require the exact qualified C49/C50
component/header/section provenance and exact source-derived recipe bytes.
The complete previous map/endpoint/frame descriptor stays unchanged. Existing
source bodies still implement actual partition, both folded-down recursive calls,
captures and pivot append; no alternate sorter is used. Object/archive clients
use ordinary `-c`/`ar rcs`; only `gs_sort` is externally defined.

The source helper borrows existing public admission and views. During emission,
eval/WHNF/substitution/typed-query advancement is forbidden and source-owner
counts stay unchanged. This is a fixed recipe/candidate, not full source action
equivalence, checked Scope evidence or a generic Identity compiler. Role value,
closure/storage/Nat/LT/array interpretation remain bounded target choices. General
native indexed/callable Acc, source erasure and accepted adoption remain separate.

Use owned disk `TMPDIR` for builds/emission. Focused `check.sh HELPER IMAGE
C50_PRODUCT CORE_CASES POINTER NEW_OUTPUT` verifies source/object/archive,
retained Core cases, resources/rollback, parent and seven new target refusals,
parameter/family/source selection refusals and exact product bytes. Full helper/
generated-source/client ASan/UBSan/leak uses separately instrumented helper plus
`CLIENT_CFLAGS`. Pointer/Core inputs stay O2; finite cases are not multiplied.

Nat32/depth256/node65536/status1–6, immutable borrowed/private-token lifetimes,
nonoverlap and transactional output persist. Overflow is unexercised and finite
